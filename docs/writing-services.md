# Writing Services

[User guide](README.md) / Writing services

Replace the [Quickstart](getting-started.md) example with your own HTTP handler.
This guide uses resident `service` mode. Generate an independent project with its
SDK using `wasmplane init my-app --language rust` or `--language moonbit`.
The examples below also apply to generated projects.

## The three application hooks

| Hook | When it runs | Typical use |
| --- | --- | --- |
| `start` | Once, before the server reports readiness | Initialization and starting background tasks |
| `handle` | For each HTTP request | Processing requests and producing responses |
| `stop` | Once during normal shutdown, after draining accepted requests | Stopping app-owned work and cleanup |

A service does not start if `start` returns an error. `stop` is not called after a
forced termination or guest trap, so complete durable updates while handling the
request. In-memory state is lost on any restart, including development reloads.

HTTP requests run one at a time, but background tasks can progress while a handler
awaits I/O. The application must preserve consistency when changing shared state
across await points.

## Rust

Replace [`examples/service-rust/src/lib.rs`](../examples/service-rust/src/lib.rs)
with the following minimal resident service, which returns a request counter.
Keep the existing `Cargo.toml` and `app.json`.

```rust
use std::cell::Cell;
use wasmplane_service_sdk::{HttpHandler, Lifecycle, json};
use wasmplane_service_sdk::types::{ErrorCode, Request, Response};

struct App;
wasmplane_service_sdk::export!(App);

thread_local! {
    static COUNT: Cell<u32> = const { Cell::new(0) };
}

impl Lifecycle for App {
    async fn start() -> Result<(), String> {
        println!("started");
        Ok(())
    }

    async fn stop() -> Result<(), String> {
        println!("stopped");
        Ok(())
    }
}

impl HttpHandler for App {
    async fn handle(_request: Request) -> Result<Response, ErrorCode> {
        COUNT.set(COUNT.get() + 1);
        Ok(json(format!("{{\"count\":{}}}", COUNT.get())))
    }
}
```

```sh
wasmplane dev examples/service-rust/app.json
```

`json` sets the response body to a JSON string and adds `content-type: application/json`.
It does not serialize values; construct or serialize the JSON in your application.

Use `request.get_path_with_query()` for routing and `response.set_status_code(...)`
to set the response status. Standard WASIp3 types and APIs are available through
`wasmplane_service_sdk::wasip3` and `wasmplane_service_sdk::types`.

The example's Cargo configuration includes:

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
wasmplane-service-sdk = { path = "../../sdk/rust" }
```

Run the component produced for the `wasm32-wasip2` target. Despite the target's name,
the SDK exports WASIp3 HTTP and async lifecycle hooks. Apps generated by `init`
use the SDK path `vendor/wasmplane-sdk`, so the entire project can move to another
directory or repository and still build. For an independent Cargo package inside
this repository, add an empty `[workspace]` to its `Cargo.toml`, or add it to the
root workspace's `exclude` list.

## MoonBit

Replace [`examples/service-moonbit/app.mbt`](../examples/service-moonbit/app.mbt)
with the following code. Keep `moon.pkg.json` and `app.json`.

```moonbit
let count : Ref[Int] = { val: 0 }

pub async fn start(_background_group : @async-core.TaskGroup[Unit]) -> Result[Unit, String] {
  @service.log("started")
  Ok(())
}

pub async fn stop(_background_group : @async-core.TaskGroup[Unit]) -> Result[Unit, String] {
  @service.log("stopped")
  Ok(())
}

pub async fn handle(request : @types.Request, _background_group : @async-core.TaskGroup[Unit]) -> Result[@types.Response, @types.ErrorCode] {
  request.drop()
  count.val += 1
  Ok(@service.json("{\"count\":\{count.val}}"))
}
```

```sh
wasmplane dev examples/service-moonbit/app.json
```

`@service` provides SDK helpers, `@types` provides WASI HTTP types, and `@async-core`
provides generated async runtime types. These imports are already defined in
`moon.pkg.json`. Release WASI resources after use. This example does not inspect
the request, so it calls `request.drop()` at the beginning.

The build copies every `.mbt` file directly under the application directory, along
with `moon.pkg.json`, into the generated tree and connects them to the shared WIT
handler. Multiple files in the same package are supported; additional packages in
subdirectories require extending the build pipeline. `target/generated` is recreated
on every build. Generated projects produce `my-app/target/service.wasm`; the repository
example produces `examples/service-moonbit/target/service.wasm`.

## Timers and background tasks

Wait with `wasmplane_service_sdk::sleep_ms(100).await` in Rust or
`@service.sleep_ms(100UL)` in MoonBit. Other async work can progress during the wait.
Use a timer instead of a busy loop.

Start background work with `wasmplane_service_sdk::wasip3::wit_bindgen::spawn_local`
in Rust or with `background_group.spawn_bg` from MoonBit's `start` hook.
The original [Rust](../examples/service-rust/src/lib.rs) and
[MoonBit](../examples/service-moonbit/app.mbt) examples set a shared shutdown flag in
`stop`. The runtime drives tasks even while no requests arrive, but discards them
when the application exits.

## Files, environment variables, and external services

The shared SDK provides `env`, `read_file`, `write_file`, `fetch`, and Durable Object
calls. See the [Shared I/O SDK](sdk-io.md) for types, examples, and permissions.
File and HTTP reads take explicit byte limits and return WASI errors.
The same access-grant and denial tests run against both Rust and MoonBit.

## Package the SDKs

Run `just sdk-pack` from the runtime source tree to produce local distribution files:

- `target/sdk-packages/wasmplane-service-sdk-0.1.0.crate`
- `target/sdk-packages/wasmplane-moonbit-service-sdk-0.1.0.tgz`

The Cargo package is verified by compiling its extracted contents. The MoonBit
package includes WASI and Durable Object WIT contracts as regular files.
`just sdk-test` extracts both packages outside this repository and builds generated
apps against them. These commands do not publish to a registry. For normal use,
`init` is enough to get started.

Extract the Rust `.crate` and use its directory as a Cargo path dependency.
Install the MoonBit `.tgz` with
`pnpm add /absolute/path/to/wasmplane-moonbit-service-sdk-0.1.0.tgz`;
`@wasmplane/moonbit-service-sdk/build` exports `build(appDirectory)`.
The app's generated binding imports continue to use `wasmplane/service-sdk/...`.

## Verify the application

For component-level assertions, export functions such as
`pricing-test: func() -> result<_, string>` from a test world and run
`wasmplane test tests.wasm`. Both Rust and MoonBit support async tests with the
same host permissions as the service. See [testing](testing.md) and the
[exported test examples](../examples/testing/README.md).

```sh
curl http://127.0.0.1:8080
curl http://127.0.0.1:8080
```

The minimal apps above return `{"count":1}` and `{"count":2}` respectively.
Ctrl-C prints `stopped`; after restarting, the counter begins at 1 again.

`just service-test` verifies the original repository examples. It requires both
language toolchains and expects their original JSON format and test endpoints.
If you replace them with the minimal apps on this page, provide tests for your
new application behavior.
